# 2.10 Pack lifecycle

## Status

`done`

## Goal

Pack PDFs exist only while the owner downloads them from `/desk`. Leftover files under `.desk-out/` are deleted when a job is marked Applied and at the start of each weekly run. Tracker JSON (or the gist) stays the durable record.

## Why

Older weekly dry-runs wrote CV and letter PDFs into `.desk-out/`. Email no longer attaches them (`2.9`), but leftover files still sit on disk. The owner does not want an archive of application copies. See `context/progress-tracker.md`.

## In scope

- `/desk/pack` stays a streamed PDF. Do not write packs to `public/`, the gist, or `.desk-out/`.
- Gist store remains `tracker.json` only (`2.7`).
- When tracker status becomes `applied`, delete every `*.pdf` under `.desk-out/` (recursive). Keep `tracker.json`, `email.html`, `subject.txt`. If the folder is missing (Vercel), no-op. Tracker write must still succeed if delete fails.
- At the start of `buildWeeklyMail()` (dry-run and send), run the same PDF delete. That clears leftover packs from pre-`2.9` dry-runs.
- Local only for the filesystem delete. Browser Downloads are out of reach.
- Patch architecture, overlay if the store sentence changes, tracker, spec README.

## Out of scope

- Deleting files from Drive, Gmail, or the Downloads folder
- Changing pack PDF contents or `/desk` UI
- Changing email copy (`2.9`)
- Operating loop overlay (`2.11`), apply-file policy (`2.12`)
- Auto-apply
- A database or blob store
- Reopening `2.0`–`2.9` spec files

## User-facing behavior

1. Download CV or letter from `/desk`. The file is a browser download, not saved by the app.
2. Mark Applied. Any leftover `.desk-out/**/*.pdf` are removed. The tracker row stays.
3. `npm run desk:weekly -- --dry-run` also removes leftover PDFs, then writes HTML and subject only.
4. Public site unchanged.
