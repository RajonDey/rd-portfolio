# 2.5 Weekly run and email

## Status

`done`

## Goal

A weekly CLI run discovers Apply-fit jobs, compiles CV and letter PDFs, and emails the owner a shortlist (about 5–8). Local dry-run writes to `.desk-out/` and does not send. Production `/desk` stays 404. Packs are never public URLs.

## Why

The owner reviews and applies from email without sitting in `/desk` all week. Email is the remote review surface until a later spec hosts `/desk`.

## In scope

- Cap: 8 Apply hits from `runDiscovery()` (`2.4`), already sorted newest first. Fewer is fine. Zero Apply still sends a short “none this week” mail (or dry-run file).
- Compile `2.3` packs in memory. Attach CV + letter per job. Do not write to `public/`.
- Email via Resend HTTP API (`https://api.resend.com/emails`). No Resend npm package. Auth: `RESEND_API_KEY` (gitignored env / GitHub secret).
- `to`: `DESK_MAIL_TO` or `CONTACT_EMAIL` (`contact@rajondey.com`). Owner only.
- `from`: `DESK_MAIL_FROM` (Resend-verified address). Required to send.
- `npm run desk:weekly` runs `scripts/run-weekly.mjs`, which bundles `scripts/desk-weekly.ts` with `esbuild` (devDependency, named here) and executes it with Node. This avoids a tsx/React-PDF hyphenation loader bug.
- `--dry-run`: write HTML + PDFs under `.desk-out/` (gitignored). Do not call Resend.
- GitHub Action `.github/workflows/desk-weekly.yml`: Mondays 07:00 UTC and `workflow_dispatch`. Runs `npm run desk:weekly` with secrets. Does not deploy or open `/desk`.
- Reuse `2.2` scorer, `2.3` PDFs, `2.4` discovery. No LLM. No new scorer.
- Patch architecture, overlay, tracker, spec README.

## Out of scope

- Auto-submit
- Hosted production `/desk`
- Application tracker (`2.6`); repeats are allowed until then
- Public site, nav, sitemap
- Desk UI for sending mail
- Extra mail providers (SendGrid, SMTP)
- Inventing jobs, employers, or metrics

## User-facing behavior

1. Local: `npm run desk:weekly -- --dry-run`. Open `.desk-out/` HTML and PDFs. Review. Send applications by hand.
2. GitHub Action (or `npm run desk:weekly` with Resend env): owner receives one email with posting links and PDF attachments.
3. Owner opens postings, reviews PDFs, applies by hand.
4. Public site and production `/desk` unchanged (desk still 404 in production).

## Content / copy

Email subject: `Desk: {n} jobs to review` or `Desk: no jobs this week`

Email body (plain HTML, no em dashes):

- Intro: `Weekly shortlist. Review and send by hand. Nothing was submitted.`
- Per job: title, company, location, application title, posting URL
- Footer: `Skipped {n}. Scanned {n}.` plus source errors if any
- Empty: `No apply-fit jobs this week.`
