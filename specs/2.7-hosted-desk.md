# 2.7 Hosted desk

## Status

`done`

## Goal

The owner can open `/desk` on the live site from any device, sign in with the same password, scan jobs, download packs, and mark them. Marks persist and also hide jobs from the Monday email. Public nav, sitemap, and robots stay unchanged.

## Why

Local `next dev` is not enough if the owner wants to check and apply from anywhere. Vercel already hosts the site. The filesystem tracker from `2.6` does not survive there, and the GitHub Action never saw it.

## In scope

- Open `/desk` when `DESK_PASSWORD` is set (local and Vercel). Missing password still 404.
- Same password form as local. Wrong password still 404. `noindex`, not in nav, sitemap, or footer. `robots.txt` still disallows `/desk`.
- Session cookie: `secure` on HTTPS production.
- Tracker: if `DESK_GIST_ID` and `DESK_GIST_TOKEN` are set, read/write `tracker.json` on that secret gist. Otherwise keep `.desk-out/tracker.json` (local).
- GitHub Action weekly job passes the same gist env so Monday mail skips tracked URLs.
- Patch architecture, overlay, tracker, spec README.

## Out of scope

- Auto-apply
- Clerk / OAuth / a database
- Nav or footer link to Desk
- A public “login” brand page, OG, or sitemap entry
- NL sponsor list, Canada Job Bank, interview prep
- Changing fit rules, ATS boards, or weekly cap

## User-facing behavior

1. Owner sets `DESK_PASSWORD` on Vercel (Production). Visit `https://portfolio.rajondey.com/desk`. Password form. Open.
2. Find jobs, download pack, mark Applied / Interview / Skip / Silence. Apply on the company site by hand.
3. Without the password env, `/desk` is still 404.
4. Public pages unchanged.
