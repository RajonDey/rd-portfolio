# 0.0 AI-dev workflow

## Status

`done`

## Goal

Make this repo assistant-friendly: durable project context, a spec handoff folder, and a navigator (`AGENTS.md` / `CLAUDE.md`) so agents open the right files instead of scanning the whole tree.

## Why

Future work (IA, showcase, content, SEO) should start from shared context plus a written spec, not from a cold codebase tour each session.

## In scope

- Write first-draft `context/*` from the live codebase.
- Add `AGENTS.md` (full navigator) and `CLAUDE.md` (pointer).
- Add `specs/` with README, template, and this example spec.
- Add `.cursor/rules/spec-workflow.mdc` (always apply).
- Record state in `context/progress-tracker.md`.

## Out of scope

- Implementing product features (showcase, SEO migration, type unification).
- Rewriting application UI.
- Filling specs `0.1+` (owner will provide further context first).

## User-facing behavior

No visitor-facing change. Developers / agents:

1. Open a task.
2. Read `AGENTS.md` → `context/progress-tracker.md`.
3. For features, wait for or write a `ready` spec under `specs/`.
4. Touch only the files the navigator names.
