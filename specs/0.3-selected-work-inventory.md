# 0.3 Selected work inventory

## Status

`done`

## Goal

Home will later show **three** evidence items. `/work` will show **six** selected pieces, in a fixed order. Both lists use only records that already exist in `src/lib/portfolio.ts` plus the IEEE paper already in `src/lib/site.ts`. No new case studies, metrics, or quotes.

## Why

Hiring managers should see judgment, not the full archive. `context/portfolio-v2.md` already named the mix: one healthcare or enterprise case, one product you own, the IEEE paper on home. `/work` is 4–6 production pieces. This spec names them. Depends on `0.1` and `0.2`. Listed next in `context/progress-tracker.md`.

## In scope

- Lock the three home evidence items (data only; home UI is `0.4`).
- Lock the `/work` shortlist and display order.
- Add a small helper in `src/lib/` that returns those entries. `/work` reads it instead of `getAllPortfolioEntries()`.
- Unselected records stay in `portfolio.ts`. Direct `/work/[slug]` URLs still resolve. They just leave the `/work` list.

## Out of scope

- Rebuilding home as a document (`0.4`). Do not change the home featured-project cards in this spec.
- Rewriting case-study or project-detail bodies (`0.5`).
- Adding or inventing case studies, metrics, or a blog post.
- Putting IEEE on `/work` as a seventh card. IEEE is home evidence + `/writing`.
- Email-template work, WordPress brochure sites, or ClipKit on the selected lists.
- Visual system (`0.8`). Retiring `/projects` (`0.9`).

## User-facing behavior

1. Open `/work`. Six titles, in the order below. No search, no filters, no extra archive items.
2. Each selected row still links to `/work/{slug}` (or the existing live URL if that record has no internal page).
3. Open `/work/calystapro-emr` (or another unlisted slug such as `enterprise-email-development-jnj`). The page still loads. It is just not on the `/work` list.
4. Open `/`. Unchanged from `0.2` (still the stacked v1 home). The three home proofs are stored for `0.4`.
5. Open `/writing`. Still IEEE only (`0.2` / `0.6`).
