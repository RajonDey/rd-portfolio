# 2.6 Application tracker

## Status

`done`

## Goal

On `/desk`, the owner records applied / interview / skip / silence for a posting. Tracked jobs do not return in Find jobs or in a local weekly run. The store is gitignored JSON. Production `/desk` stays 404.

## Why

Without a tracker, the same Apply hits come back every scan and every local weekly pack.

## In scope

- Gitignored store: `.desk-out/tracker.json` (same folder as weekly dry-run). Never commit. Never put in `public/`.
- Statuses the owner sets (do not invent outcomes): `applied`, `interview`, `skip`, `silence`. All four hide the job from new packs. `silence` means hide without applying.
- Identity: normalized posting URL (no hash/query, lowercase, no trailing slash).
- `GET`/`POST /desk/track`. Session required. Unauthenticated 404. POST upserts a row. POST `status=clear` removes the row so it can return.
- Signed-in `/desk`: tracker list (title, company, status, Open posting, status buttons, Clear). Discover Apply rows get the same status buttons; after a mark, that row leaves the scan list.
- Paste-JD Apply result can mark when a job URL was submitted.
- `runDiscovery()` drops tracked URLs from Apply hits, so local `desk:weekly` is covered too.
- GitHub Action weekly run has no tracker file (fresh checkout). That limitation is locked; do not add a database or gist sync in this unit.
- Patch architecture, overlay, tracker, spec README.

## Out of scope

- Auto-apply
- Gmail inbox parsing
- Interview prep pack
- Hosted production desk / remote tracker
- Vercel env for the tracker
- Inventing that a job was applied or interviewed

## User-facing behavior

1. Sign in on `/desk`. Find jobs.
2. For an Apply row: Open posting, download pack, mark Applied / Interview / Skip / Silence.
3. That job disappears from the scan and from the next local weekly run.
4. Tracker list shows recorded jobs. Change status or Clear.
5. Public site unchanged.
