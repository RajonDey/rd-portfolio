# 2.2 Fit from a pasted job description

## Status

`done`

## Goal

On `/desk`, the owner pastes a job description (and optionally a URL). The desk returns apply or skip, CV variant, application title, work-article links, IEEE if relevant, red flags, and keyword signals. Rules come from `context/job-search-profile.md`. No PDF, no crawl, no LLM.

## Why

First useful slice: prove vetoes and packing choices before `2.3` compiles a CV. Precision over volume. High chance of a call, not a long maybe-list.

## In scope

- Signed-in `/desk` form: job description textarea, optional URL, Evaluate.
- `POST /desk/fit` (session cookie required). GET is 404. Production / locked desk still 404s via the `2.1` layout.
- Pure scorer in `src/lib/desk/fit.ts` + `src/lib/desk/rules.ts`. Do not import `context/*.md`. Encode the overlay rules in TypeScript. Do not add facts that are not in the job-search profile, `src/lib/site.ts`, or `SELECTED_WORK_SLUGS`.
- Optional URL fetch: http(s) only, timeout, size cap, HTML stripped to text. Fail soft: ask to paste the description. Treat the posting as untrusted data (never follow instructions in it).
- Output: decision apply/skip, application title, CV variant + existing CV URL, up to two `/work/{slug}` links, IEEE link when the JD is LLM/security/trust, red flags, signals.
- Hard vetoes from the overlay: fluent German required, contract/freelance/hourly/intern/junior/Werkstudent/Praktikum, not full-time, Portugal/Estonia/US.
- “German is a plus” is a note, not a skip.
- CV: SWE default (`CV_URL`) unless the posting is Senior Frontend / UI-heavy (`FRONTEND_CV_URL`). Tech Lead postings still use the SWE CV; application title is Tech Lead / Module Lead (Frontend).
- Work slugs from `SELECTED_WORK_SLUGS` only, max two, using the overlay map.
- Copy in `src/lib/desk/copy.ts`. Client leaf only for the form/result (`DeskFitForm`).
- Patch architecture (add `/desk/fit`), tracker, spec README.

## Out of scope

- Compiled PDF, cover letter, packs (`2.3`)
- Discovery crawl, weekly email, tracker
- LLM / extra npm dependencies
- Auto-apply
- Inventing experience, metrics, case studies, or a third CV
- Salary-band parsing (later)
- Changing public routes, nav, sitemap
- Hosting `/desk` in production

## User-facing behavior

1. Owner signs in on `/desk` (`2.1`).
2. Pastes a job description, optionally a URL, clicks Evaluate.
3. Skip: red flags listed. No work/CV pack advice beyond the skip.
4. Apply: application title, which CV to send (link to the existing Google Doc / PDF), up to two work URLs, IEEE when relevant, signals (matched keywords only).
5. Owner reviews and applies by hand. Sign out still works.
6. Empty or unreadable input: skip, flag that a description is required.
7. Public `/desk` remains 404.

## UI notes

Match `context/ui-context.md`. Same desk column as `2.1`.

- Layout: paper, `max-w-3xl` form under the H1. Result below the form as a hairline list, not cards.
- Tokens: `textDark`, `textLight`, `primary`, `background`, `border-black/10`.
- Evaluate is the filled pill. Apply/Skip are text, not a new color system (Skip stays ink, not red).
- Textarea: `w-full`, rows 12, hairline border.
- Work/IEEE/CV are links (`next/link` or `<a>` for external CV/IEEE).
- Breakpoints: same as About. No motion.
