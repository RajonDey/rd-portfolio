# 2.23 Desk store reliability

## Status

`done`

## Goal

On `/desk`, marking Applied / Skip / Interview / Silence and saving Notes either persist and show in Tracker / Notes, or the UI shows a clear failure. Hosted desk requires the gist store; silent 404s on write go away.

## Why

Review found: Applied on an Inbox row (e.g. Fullstack Engineer, Frontend-leaning) did not appear in Tracker, and Notes Save did not stick. Today writes fail closed as HTTP 404 with almost no UI feedback on Applied. On Vercel, without `DESK_GIST_ID` + `DESK_GIST_TOKEN`, filesystem writes do not survive. Local `.env.local` currently has password but no gist env; local `tracker.json` is empty. See owner review notes and `context/progress-tracker.md`.

## In scope

- Surface store mode on signed-in `/desk` (one quiet line): `Local file` when gist env is unset; `Gist` when set. If a write fails, show a visible error (reuse Notes fail pattern for Tracker marks too).
- Applied / Skip from Inbox: on failure, keep the row and show `Could not save that mark.` Do not hide the Inbox row unless the POST succeeded.
- Tracker list reload after a successful mark (keep the existing event). After a failed mark, do not pretend success.
- Notes: keep existing fail copy; ensure POST failures stay visible (already mostly true).
- Hosted reliability (docs + soft gate, not a new database):
  - Document owner setup: secret gist with `tracker.json` (`{"jobs":[]}`) and `feedback.json` (`{"notes":[]}`); `DESK_GIST_ID` + `DESK_GIST_TOKEN` on Vercel Production and GitHub Action secrets.
  - When `VERCEL=1` (or production) and gist env is missing, show a one-line warning under the Desk H1: marks and notes will not persist. Do not invent a database.
- Optional GET `/desk/track` / notes already work; no shape change to `tracker.json` or `feedback.json`.
- Patch overlay one line, architecture env note, progress tracker, spec README.
- Copy in `src/lib/desk/copy.ts`.

## Out of scope

- Inbox scan cache (that is `2.24`)
- Google Docs / cover-letter tabs (`2.25`)
- Weekly OS database, Supabase, Google Sheets as the store
- Changing fit, discovery sources, or weekly cap
- Auto-apply
- Reopening `2.0`–`2.22` as new features (bugfix only here)

## User-facing behavior

1. Sign in on `/desk` (local or live).
2. See a quiet store line: Local file or Gist. On live without gist env, also see a persist warning.
3. Mark Applied on an Inbox row. On success: row leaves Inbox, Tracker lists it. On failure: row stays, error line shows, Tracker unchanged.
4. Save a Note. On success it lists. On failure, existing fail copy shows.
5. Public site unchanged.
