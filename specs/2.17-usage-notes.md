# 2.17 Usage notes

## Status

`done`

## Goal

Signed-in `/desk` has a small Notes area. The owner can jot issues and ideas while using Desk so they are not lost. Later we turn a note into a spec, then implement. No database.

## Why

Real use will surface friction. Those notes must survive on the live desk (`portfolio.rajondey.com/desk`), not only on one laptop. The tracker already uses a secret gist or `.desk-out/` JSON. Notes use that same store. See `context/progress-tracker.md`.

## In scope

- Same URL `/desk`. Closed `<details>` **Notes** after Paste a job. Paper/ink, no new colors or routes that are public.
- `GET`/`POST /desk/notes`. Session required. Unauthenticated 404. GET lists notes. POST `text` appends. POST `id` + `status=clear` removes one note after it has been specced.
- Store: gist file `feedback.json` when `DESK_GIST_ID` + `DESK_GIST_TOKEN` are set (live). Else `.desk-out/feedback.json` (local). Never `public/`. Never a database. Do not put notes in `tracker.json`.
- Shape: `{ notes: [{ id, text, createdAt }] }`. Newest first. Text trimmed, max 2000 characters. Keep at most 80 notes (drop oldest).
- Copy in `src/lib/desk/copy.ts`. Overlay one line. Patch architecture, progress tracker, spec README.

## Out of scope

- Database, Clerk, extra gist, emailing notes
- Browser-only localStorage as the live source of truth
- Auto-creating specs from notes
- Public site UI
- Auto-apply
- Reopening `2.0`–`2.16`

## User-facing behavior

1. Sign in on `/desk` (local or live).
2. Open Notes. Paste a short issue or idea. Save.
3. The note stays on the next visit (gist on live, file locally).
4. After we write a spec and ship it, Clear that note.
5. Public site unchanged.
